# 通用游戏策划工作台

- 日期：2026-08-11
- 状态：首期范围已确认，后续持续扩展

## 背景与目标

当前仓库的核心产品是挂机游戏。需要一个独立的纯前端策划工作台，把外部游戏研究、属性拆解、战斗机制和当前项目的设计启发放在同一处，后续继续服务角色、装备、技能、掉落和战斗系统开发。

《诸天刷宝录》只是第一份研究样本，项目命名、数据结构和界面不绑定它。

## 核心需求

- 使用 React + Vite + TypeScript，保持纯前端，不引入后端。
- 将研究资料拆成基础属性、战斗属性、特殊属性和机制观察四个入口。
- 每个属性条目展示作用范围、对当前项目的设计启发、标签、证据等级和来源链。
- 允许按分类浏览，并通过关键词搜索属性、标签和用途。
- 保留“待实机核验”状态，避免将玩家实测公式误当作官方硬规则。
- 使用项目内独立 `.gitignore` 忽略依赖、构建产物、环境文件、编辑器文件和临时缓存。

## 约束

- 新项目位于当前目录下的 `game-design-lab`，不改动现有 `egg-jianghu` 应用入口。
- 视觉和文案服务于策划阅读，不展示内部实现标识，也不假设未来一定使用某个后端。
- 公开资料只做可追溯的研究输入；版本敏感数值进入验证队列。

## 方案与决策

### 选定方向

采用“属性目录 + 详情面板 + 机制观察 + 待核验队列”的研究工作台。数据先集中在 TypeScript 中，等属性模型稳定后再拆成更细的角色、装备、技能和公式模块。

### 选择理由

- 能在一次阅读中看到属性分类、单条说明和证据链。
- 研究样本替换成本低，适合继续服务当前项目而不是做单款游戏百科。
- 纯前端静态数据足以支撑第一阶段，不提前引入数据库和接口复杂度。

## 当前研究结论

- 五项成长值是勇、智、体、敏、精；社区资料常用勇×敏、智×敏、体+精等启发式筛选角色定位。
- 核心面板包括生命、物理攻击、法术攻击、物理防御、法术防御和速度。
- 战斗词条应拆成输出、防御、命中/易伤、治疗/护盾和技能循环多个结算层。
- 已拿到一份玩家整理的完整伤害公式：攻防核心项 `A² / (A + D)` 的两端各自是“面板 × 修正 × 职业系数”，之后依次乘技能描述系数、加法增伤池、暴击系数、增效 BUFF、减伤、抗性、三层目标易伤和最终层。
- 暴击系数是唯一不自带 100% 底数的乘区（初始 150%），因此爆伤每点边际收益高于终伤，玩家结论是先无脑堆爆伤；但 `1 : 7` 只是暴击系数≈7 时的快照，不是常数。
- 攻击面板的收益弹性为 `(A + 2D) / (A + D)`，上限 2，所以面板词条只在越级时才值得与爆伤竞争。
- 速度、能量、冷却和自动技能优先级共同决定 Build 是否闭环。
- 召唤、元素、技能类别、武器类型与经验/掉落/经营收益属于特殊或跨系统属性。
- 玩家实测公式、当前版本上限、取整顺序、AI 完整条件和召唤继承比例仍需客户端或训练场复核。
