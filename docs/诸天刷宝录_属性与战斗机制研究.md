# 《诸天刷宝录》属性与战斗机制研究

> 研究日期：2026-08-01<br>
> 研究目的：拆解《诸天刷宝录》的角色属性、派生战斗属性、行动时间轴、技能 AI、伤害结算与 Build 结构，为挂机 RPG 的战斗设计提供机制参考。<br>
> 版本口径：正式版资料以标题标注 `1.2.2.0` 的社区指南为主；伤害与速度公式来自玩家实测，主要形成于 2025 年；技能数据库为 `v0.8.17.0` 历史快照，只用于确认字段结构和技能范式，不代表当前技能总数。

## 1. 结论摘要

《诸天刷宝录》表面是回合制自动战斗，底层更接近 **ATB 行动条 + 能量 + 实时冷却** 的混合系统。

它的战斗强度主要由四层共同决定：

1. **角色成长值**：勇、智、体、敏、精决定物攻、法攻、物防、法防、生命与速度的成长方向。
2. **职业与技能被动**：当前职业提供独立乘区；所有已学技能的被动属性会叠到角色身上，不要求技能进入自动释放栏。
3. **战斗循环**：敏捷决定行动频率；初始能量、每回合能量回复、技能消耗、技能冷却共同决定技能能否稳定循环。
4. **伤害词条**：基础攻防结算之后，再经过加法增伤池、暴击、减伤/抗性、受伤加深和最终增减伤等多个乘区。

最重要的机制结论：

- **敏捷不是单纯先手属性，而是行动次数属性。** 高速角色可能在低速角色行动一次前行动两次。
- **速度收益经过平方根压缩。** 速度越高仍越快，但边际收益递减，避免行动频率随速度线性失控。
- **Build 的核心不是单项战力，而是循环能否闭合。** 速度再高，如果缺能量或技能仍在 CD，行动只能退化为普通攻击。
- **自动战斗存在明确的技能优先级。** 通用 AI 从左到右检查技能，满足能量、CD 和场景条件时使用最靠左的技能。
- **伤害不是简单的 `攻击 - 防御`。** 核心攻防项使用 `A² / (A + D)`，防御是平滑减伤而非硬减法。
- **词条存在不同结算层。** 物理/法术、元素、技能专精、武器掌握等进入同一加法池；暴击与最终增伤处于其他乘区，因此均衡乘区通常优于只堆一种词条。

## 3. 属性系统

### 3.1 五项成长值

游戏用“勇、智、体、敏、精”描述角色成长方向。它们更接近 **成长系数/资质**，不是最终战斗面板本身。

| 成长值 | 主要影响 | 战斗定位 |
|---|---|---|
| 勇 | 物理攻击成长 | 物理输出、物理技能与普攻 |
| 智 | 法术攻击成长 | 法术输出、治疗和多数护盾 |
| 体 | 物理防御与生命成长 | 抵抗物理伤害、提高生存 |
| 敏 | 速度成长 | 行动频率、先后手、循环效率 |
| 精 | 法术防御与生命成长 | 抵抗法术伤害、提高生存 |

社区角色成长表常用以下三个组合做角色定位筛选：

- 物理输出潜力：`勇 × 敏`
- 法术输出/治疗潜力：`智 × 敏`
- 坦度潜力：`体 + 精`，但主队坦克还必须单独检查敏捷

这些组合是 **角色筛选启发式**，不是最终伤害公式。它们没有纳入装备、技能被动、职业倍率、暴击、元素、命盘与天命等因素。

### 3.2 基础战斗面板

五项成长值最终参与形成以下核心面板：

- 生命
- 物理攻击、法术攻击
- 物理防御、法术防御
- 速度

当前职业、装备、技能被动、宠兽、副官、命盘、科技与其他养成系统会继续修正这些面板。伤害公式指南给出的结构是：

```text
有效物攻/法攻
=（基础攻击 + 装备攻击）
 ×（对应成长修正 + 技能被动修正）
 × 当前职业攻击系数

有效物防/法防
=（基础防御 + 装备防御）
 ×（对应成长修正 + 技能被动修正）
 × 当前职业防御系数
```

这里最值得借鉴的是：**职业不是简单加点，而是独立乘法系数。** 已解锁但未装备的职业不生效，只有当前职业提供战斗属性与可用技能类别。

### 3.3 派生词条分组

角色面板还包含大量派生属性，可按功能分成六组。

#### 输出组

- 物理增伤、法术增伤
- 普攻增伤
- 元素增伤
- 技能专精效果
- 武器掌握/熟练增伤
- 暴击率、暴击伤害
- 最终增伤

#### 防御组

- 物理减伤、法术减伤
- 元素抗性
- 最终减伤
- 闪避、闪避修正
- 受疗效果
- 护盾上限、护盾加成

#### 命中组

- 命中
- 命中修正
- 闪避
- 闪避修正

“命中”与“命中修正”不是同一属性，“闪避”与“闪避修正”也不是同一属性。

#### 循环组

- 初始能量
- 每回合能量回复
- 技能冷却缩减
- 速度
- 增益持续时间
- 减益持续时间

#### 召唤组

- 召唤强度：提高召唤物基础属性，不直接提高召唤物的所有派生修正
- 召唤数量：增加可同时存在的召唤物数量

#### 非战斗组

- 经验加成、职业成长、技能学习
- 工作效率、掉落率及各种经营能力

它们不直接参与单次伤害，但会显著改变成长速度和刷宝效率。

### 3.4 元素、技能类别与武器掌握

一个伤害技能通常同时带有三类标签：

1. **伤害性质**：物理或法术。
2. **元素**：木、水、精神、火、土、雷、神圣、暗等。
3. **技能类别**：战技、箭弩、方术、武功、符咒、神技、魔法、斗气、召唤、忍术、机甲、医术、枪械、功法、异能等。

此外，角色还可能从实际装备的武器获得对应掌握增伤。因此，一个“火属性、物理性质、斗气类别、拳指武器”的技能，能同时吃到：

- 物理增伤
- 火系增伤
- 斗气效果
- 拳指掌握

这些词条在玩家实测公式中进入同一个加法增伤池。

## 4. 战斗流程

### 4.1 队伍与站位

- 主队固定最多 6 人。
- 阵型是格子化布局，技能目标可表现为单体、直线、横排、十字、周围、特定范围或全体。
- 站位不只是前后排概念，还决定范围治疗、范围护盾、范围攻击和邻接效果能覆盖谁。
- 实战常通过“高速辅助先加能量 → 坦克开减伤/控制 → AOE 清场 → 单体技能收 Boss”的顺序编排队伍速度。

### 4.2 ATB 行动条

所有单位从行动条左侧向右移动，到达最右端时获得行动机会。移动速度取决于角色速度面板。

玩家实测的单次行动间隔为：

```text
行动间隔（秒）
= 100 / sqrt[面板速度 ×（1 + 速度 Buff）] / 2
= 50 / sqrt[有效速度]
```

例：有效速度为 `5000` 时，行动间隔约为：

```text
50 / sqrt(5000) ≈ 0.707 秒
```

这意味着速度翻倍不会让行动频率翻倍。若希望行动间隔减半，理论上需要约四倍有效速度。

游戏内的 `×1～×4` 战斗速度只是加快演出与处理速度，不改变单位之间的相对行动逻辑。

### 4.3 行动决策与自动技能 AI

角色获得行动机会后，可以普通攻击或释放技能。自动战斗的通用 AI 规则可概括为：

1. 从自动技能栏最左侧开始检查。
2. 如果能量足够、技能不在冷却，并且场景条件成立，则释放该技能。
3. 如果不成立，继续检查右侧技能。
4. 如果没有可用技能，则使用职业或武器提供的零消耗普通攻击。

AI 还包含少量语义判断：

- 没有死亡队友时不会释放复活。
- 治疗角色可能在技能不适合当前治疗需求时改用治疗型普通攻击。
- 某些技能的目标选择遵循自身逻辑，不一定完全符合玩家期望。

因此，自动技能栏本质上是一条 **优先级队列**，不是简单的循环播放列表。

### 4.4 已学技能、自动技能与被动

- 当前界面手册记录每个角色最多可持有 12 门技能。
- 技能不必放进自动技能栏，其被动属性依然会作用于角色。
- 技能学习受到职业类别约束；通用技能可被所有职业使用。
- 切换到不匹配的职业后，对应技能的职业相关被动可能不再生效。
- 普通攻击由当前职业决定，部分武器会覆盖职业普通攻击。

这一设计把技能拆成两个价值面：

- **主动价值**：技能是否进入自动释放优先级、消耗多少能量、覆盖什么目标。
- **被动价值**：即使永不释放，仍可作为物攻、法攻、生命、防御或速度的成长节点。

### 4.5 能量与冷却

技能循环同时受两道门槛限制：

- **能量**：技能消耗 1～5 点能量；初始能量只在开战时提供；能量回复在角色每次行动时结算。
- **冷却**：技能释放后进入以秒计的 CD；正式版社区资料记录冷却缩减上限为 95%。

`v0.8.17.0` 的 216 门技能快照显示，除 1 门零消耗/零 CD 技能外，其余技能全部遵循：

| 能量消耗 | 基础 CD |
|---:|---:|
| 1 | 4 秒 |
| 2 | 8 秒 |
| 3 | 12 秒 |
| 4 | 16 秒 |
| 5 | 20 秒 |

这说明旧版技能的能量成本和基础 CD 使用统一预算：**每 1 点能量对应 4 秒基础 CD**。正式版新增技能可能打破该规律，应把它视为历史设计规律而不是硬编码事实。

高冷却缩减并不总是正收益：

- 输出角色可以借助高回能与高减 CD，让两个低费 AOE 形成近似无限循环。
- 坦克或辅助如果减 CD 过高，AI 可能反复释放前两个高优先级技能，使第三个关键技能永远排不到。
- 过度频繁释放也会造成能量枯竭，使循环断档。

所以真实循环约束是：

```text
单位时间有效施法次数
= min（行动机会、能量供给、CD 就绪次数、AI 优先级可达性）
```

### 4.6 胜负与挂机衔接

普通关卡支持两种自动结算方式：

- `Loop`：战斗结束后重复当前关卡。
- `Advance`：胜利后进入下一关；失败后退回上一关并切回 `Loop`。第 10 关继续前进会回到第 1 关。

中途返回会暂停战斗并进入结果界面，玩家可以继续、离开或切换到已解锁的相邻关卡；已经获得的物品和进度不会因离开而丢失。

## 5. 伤害结算

### 5.1 攻防核心函数

玩家实测的核心攻防项为：

```text
基础伤害项 = A² / (A + D)
```

- `A`：攻击方对应的有效物攻或法攻。
- `D`：目标对应的有效物防或法防。

这个函数有三个重要性质：

1. 当防御为 0 时，基础伤害项等于攻击力 `A`。
2. 当攻防相等时，基础伤害项等于 `A / 2`。
3. 防御越高，继续堆防仍有效，但收益逐渐平滑，不会像 `A - D` 那样突然变成 0 或 1。

### 5.2 完整伤害结构

将玩家实测公式按结算层重写：

```text
伤害
= [A² / (A + D)]
 × 技能倍率
 × [1 + 物理/法术增伤 + 普攻增伤 + 元素增伤 + 技能专精 + 武器掌握]
 × 暴击系数
 × [1 + 增效 Buff]
 × [1 - 物理/法术减伤]
 × [1 - 元素抗性]
 × [1 + 目标受到的物理/法术伤害增加]
 × [1 + 目标受到的元素伤害增加]
 × [1 + 目标受到的所有伤害增加]
 × [1 + 攻击方最终增伤 - 目标最终减伤]
```

这是一份玩家测试模型，不是官方公开源码。它适合解释 Build 方向，不应在缺少训练场复测时当作永久不变的精确实现。

### 5.3 加法池与乘区

同一个加法池内的词条包括：

```text
物理或法术增伤
+ 普攻增伤（仅普攻和召唤物）
+ 元素增伤
+ 技能专精
+ 武器掌握
```

同池词条数值相同时效果等价。例如对一个火系物理长柄技能：

- `物理增伤 +50%`
- `物理增伤 +20%` 与 `火系增伤 +30%`
- `物理增伤 +20%`、`火系增伤 +15%`、`长柄增伤 +15%`

在该模型内都是同样的 `+50%`。

暴击伤害和最终增伤位于其他乘区。若一个乘区已经极高，继续堆同一乘区的边际收益会下降，把资源补到较低乘区通常更有效。

正式版综合攻略按常见词条供给量给出经验目标：

```text
暴击伤害 :（100% + 加法池）:（100% + 最终增伤）≈ 4 : 2 : 1
```

这是按词条获取比例推导的 Build 启发式，不是伤害公式强制比例。

### 5.4 暴击

- 暴击率可堆到 100%。
- 暴击伤害在实测公式中直接作为系数使用，不要再次写成 `1 + 暴击伤害`。
- 例如面板暴击伤害显示为 `200%` 时，实测模型按 `×2.0` 处理，而不是 `×3.0`。

### 5.5 命中与闪避

玩家实测公式为：

```text
闪避率
= 1 - [(1 + 命中修正) / (1 + 闪避修正) × 97%]
```

- 闪避率上限为 70%。
- 命中率与闪避率互补：`命中率 = 1 - 闪避率`。
- 例：敌方有 `20%` 命中修正时，要达到 `70%` 闪避率，约需 `288%` 闪避修正。

这里的 `97%` 表明在双方都没有修正时，基础命中率约为 97%、基础闪避率约为 3%。

### 5.6 最终减伤

当前社区实测记录最终减伤面板上限按 80% 计算，但最终增伤会在同一乘区抵消它：

```text
最终层系数 = 1 + 攻击方最终增伤 - 防守方最终减伤
```

例如防守方有 `80%` 最终减伤，攻击方有 `20%` 最终增伤：

```text
1 + 20% - 80% = 40%
```

最终表现是该层提供约 60% 减伤，而不是 80%。

### 5.7 治疗与护盾

- 多数治疗技能按施法者法攻回复生命。
- 多数护盾技能同样按法攻生成护盾，因此高智/高法攻坦克可以兼顾厚盾。
- 默认护盾容量上限约为目标最大生命的 100%；“护盾上限”可提高容纳量。
- “治疗加成”影响施法者治疗量，“受疗效果”影响目标实际收到的治疗量，两者不是同一个属性。

## 6. 状态、控制与技能范式

历史技能表反映出以下稳定范式。

### 6.1 持续伤害与持续治疗

- 中毒、流血、燃烧：每秒造成伤害。
- 恢复、不屈：每秒恢复生命。

这些效果按真实时间持续结算，因此同时受持续时间和战斗处理速度影响，但 `×1～×4` 只会加快整场模拟，不改变相对收益。

### 6.2 控制与行动条

- 晕眩、麻痹：目标无法行动。
- 减速、极寒：降低速度，从而延后下一次行动。
- 加速、狂暴：提高速度。
- 部分技能直接增加行动槽百分比，可视为立即推进 ATB 进度。

控制的价值会随速度放大：高速控制者能更频繁刷新控制，而减益持续时间决定控制能否覆盖下一次施法窗口。

### 6.3 攻防与易伤

- 利刃、凝神：提高物攻/法攻。
- 坚固、坚韧：提高物防/法防。
- 破甲、战栗、弱点：降低目标防御。
- 增伤、标记：提高目标受到的全部伤害。
- 免伤、守卫、防守姿态、近战姿态：降低受到的伤害。
- 无敌在后续正式版资料中已改为 95% 减伤，不应再按真正免疫理解。

### 6.4 “积层 → 消耗”技能链

多套技能围绕专属资源构筑：

- 剑势、专注、仁心、怒气、箭伤、燃烧等先由前置技能叠层。
- 高费技能消耗层数，按层数提高伤害、治疗或特殊效果。

这让同职业的技能不是独立按钮，而是一套生成器与终结技组合。

### 6.5 召唤

召唤技能可生成物攻型、法攻型或治疗型召唤物。召唤物受召唤强度、召唤数量以及普攻增伤等专属规则影响。召唤既能补输出，也能通过额外单位承伤提高队伍容错。

## 7. Build 机制的真实优先级

### 7.1 先解决循环，再谈单次伤害

一个输出 Build 应按以下顺序检查：

1. 能否在关键敌人行动前出手。
2. 能量回复能否覆盖目标技能成本。
3. CD 是否能在下一次行动前结束。
4. AI 优先级是否会稳定选到目标技能。
5. 满足前四项后，再优化攻防、暴击和增伤乘区。

若只提高面板攻击，却不能让技能循环起来，实战收益可能低于增加速度或回能。

### 7.2 速度不是全队无脑堆满

速度有两种用途：

- **吞吐量**：单位时间获得更多行动。
- **编排顺序**：让辅助、坦克、AOE、单体收割按预期先后行动。

全队同时追求最高速度可能破坏技能链。例如坦克先行动但尚未获得辅助补能，可能无法开出关键 3 费减伤；单体输出早于 AOE 行动，也可能把攻击浪费在小怪上。

### 7.3 输出、坦克与辅助的属性判断

| 定位 | 首要条件 | 次要条件 |
|---|---|---|
| 物理输出 | 勇、敏、物攻、目标技能循环 | 暴击、元素、专精、掌握、最终增伤 |
| 法术输出 | 智、敏、法攻、目标技能循环 | 暴击、元素、专精、最终增伤 |
| 治疗/护盾 | 智/法攻、敏、回能 | 治疗加成、受疗效果、护盾上限、持续时间 |
| 坦克 | 体、精、生命、敏 | 减伤、抗性、受疗、增益/减益持续时间 |
| 控制辅助 | 敏、减益持续时间、回能、CD | 命中、范围、目标逻辑 |
| 召唤 | 智/法攻、召唤强度、召唤数量 | 普攻增伤、回能、CD、召唤物定位 |

### 7.4 战斗的阶段性解法

- **开荒阶段**：装备等级和基础面板提升最直接，优先让队伍站得住并形成低费技能循环。
- **中期**：开始围绕职业类别、元素、技能被动和命盘做成套 Build。
- **后期**：高减 CD、高回能、永久减伤/控制、全屏 AOE 与最终增伤成为主要机制；主输出可能压缩其他输出位的价值。

## 8. 对挂机 RPG 设计的启示

以下是从机制研究中归纳的设计结论，不是《诸天刷宝录》的官方规则。

### 值得借鉴

1. **用平方根速度公式控制行动经济**<br>
   玩家能感受到速度提升，但不会因速度翻倍就让行动次数直接翻倍。

2. **让技能同时拥有主动与被动价值**<br>
   已学技能即使不上场也提供属性，收集技能自然成为长期养成线。

3. **把自动技能栏设计成可观察的优先级队列**<br>
   玩家能通过排序、能量与 CD 设计循环，挂机战斗仍有战前策略。

4. **用 `A² / (A + D)` 替代硬减法**<br>
   攻防关系平滑，防御不会把低攻击直接压成无效伤害，也不会在跨过某阈值后突然失去价值。

5. **让站位与目标形状直接关联**<br>
   单体、直线、横排、十字、周围、全体等形状使阵型具有明确的战术意义。

### 需要规避

1. **速度过度统治所有定位**<br>
   当输出、坦克、治疗、控制都最需要敏捷时，其他成长值会沦为次级筛选项。

2. **乘区过多但界面解释不足**<br>
   物理、元素、专精、掌握、暴击、最终伤害等若不明确展示结算层，玩家很难判断词条真实价值。

3. **AI 黑箱破坏 Build**<br>
   “大致从左到右，但有自身逻辑”会导致难以解释的技能选择。设计时应公开每个技能的释放条件和当前跳过原因。

4. **高减 CD 反而卡死技能队列**<br>
   若 AI 总是优先释放最左技能，冷却越短越可能让后续技能永远不可达。应提供最低间隔、循环模式、条件式优先级或技能禁用阈值。

5. **装备等级曲线压过养成系统**<br>
   如果少量装备等级差就碾压强化、技能或角色选择，Build 决策会退化成单纯换装等数值。

## 9. 尚未确认的边界

以下内容在公开资料中没有得到足够可靠的当前版本证据：

- 当前版本所有职业的精确物攻、法攻、防御和速度系数。
- 伤害公式中每个修正项的实际取整顺序。
- 伤害浮动、最小伤害、最大伤害和溢出保护规则。
- 命中/闪避公式是否存在未公开的下限、等级差修正或特殊敌人修正。
- 持续伤害能否暴击、继承哪些增伤乘区。
- 召唤物继承施法者属性的精确比例。
- AI 对治疗、复活、护盾、召唤和目标选择的完整条件表。
- `v1.2.2.0` 新增技能是否仍全部遵循“每点能量对应 4 秒基础 CD”。
- 最终减伤 80% 上限与部分技能 95% 减伤之间的结算先后和叠加边界。

如需得到可直接复刻的数值实现，应在当前版本训练场做控制变量实验，并记录战斗日志、面板、敌我等级、职业、技能等级、装备词条和每次伤害结果。

## 10. 建议的实机验证矩阵

| 验证项 | 控制变量 | 观测值 | 目的 |
|---|---|---|---|
| 攻防函数 | 固定技能倍率与所有增伤，只改变目标防御 | 单次非暴击伤害 | 复核 `A²/(A+D)` |
| 加法池 | 分别增加等量物理、元素、专精、掌握 | 单次伤害变化 | 确认是否仍同池相加 |
| 最终增伤 | 固定其他词条，只改变最终增伤 | 单次伤害变化 | 确认独立乘区与上限 |
| 暴击系数 | 100% 暴击，改变暴击伤害 | 暴击伤害变化 | 确认面板系数解释 |
| 速度公式 | 关闭速度 Buff，测试多组速度 | 两次行动的时间差 | 拟合 `50/sqrt(speed)` |
| CD 与行动 | 固定速度，改变冷却缩减 | 同一技能相邻释放时间 | 区分行动限制与 CD 限制 |
| 能量回复 | 固定技能栏与速度，改变回能 | 每轮技能序列 | 确认回能结算时点 |
| AI 优先级 | 设置 3 个不同费用/CD 技能 | 实际释放顺序 | 归纳跳过条件 |
| 命中闪避 | 固定双方其他属性，改变命中/闪避修正 | 500～1000 次攻击命中率 | 复核公式与上下限 |
| 护盾上限 | 改变最大生命与护盾上限 | 实际可叠护盾值 | 确认默认 100% 与溢出规则 |
