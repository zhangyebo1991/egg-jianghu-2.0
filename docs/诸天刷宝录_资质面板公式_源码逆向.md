# 《诸天刷宝录》资质→面板公式 · 源码级逆向

> 研究日期：2026-08-13<br>
> 研究方式：反编译 `c3runtime.js`（NW.js / Construct 3 导出的运行时，内联了所有自定义 function 的编译后 JS 源码）<br>
> 证据等级：**A**（游戏实际运行代码，非玩家实测推断）<br>
> 与本文档配套的社区攻略口径见 [`诸天刷宝录_属性与战斗机制研究.md`](诸天刷宝录_属性与战斗机制研究.md)（玩家实测，证据等级 B/C）。

## 1. 结论摘要

《诸天刷宝录》的面板派生链路是 **指数成长**，而非线性加点：

```text
资质（勇/智/体/敏/精，角色定义表 js.json）
  └─ 角色天资 = 资质 ÷ 15
        └─ 基础核心属性 = 指数/线性公式（底数 1.0095）
              └─ × 职业属性系数（百分比）
                    └─ 最终面板
```

关键常数（从 `c3runtime.js` 反编译得到，可直接复刻）：

| 常数 | 值 | 用途 |
|---|---:|---|
| 指数底数 | `1.0095` | 核心面板指数成长，指数 = `资质 × 10` |
| 天资除数 | `15` | 资质 → 成长天资 |
| 速度除数 | `4` | 速度线性项 `150 + 体/4`（已确证） |
| 指数系数 | `5 / 1 / 0.5` | 生命 / 物攻·物防 / 法攻·法防 的缩放 |

## 3. 反编译到的公式源码

`c3runtime.js` 内联了自定义 function 的编译后代码，下列为逐字摘录（已还原变量名）：

### 3.1 角色天资 function

```js
// 成长天资（招募展示 / 创角共用）
成长天资 = Math.round(10 * (资质 / 15)) / 10    // 保留 1 位小数
// 初始天资 = 资质 + 额外成长资质 × 10
```

白板号：成长天资 = `round(10/15, 1) = 0.7`。

### 3.2 基础核心属性 function

```js
// 指数型模板（底数 1.0095，指数 = 资质 × 10）
生命 = 5   × (100 + pow(1.0095, 资质×10) × 5)   // 系数 5
物攻 = 1   × (100 + pow(1.0095, 资质×10) × 5)   // 系数 1
物防 = 1   × (100 + pow(1.0095, 资质×10) × 5)   // 系数 1（同物攻）
法攻 = 0.5 × (100 + pow(1.0095, 资质×10) × 5)   // 系数 0.5
法防 = 0.5 × (100 + pow(1.0095, 资质×10) × 5)   // 系数 0.5（同法攻）

// 线性型模板（速度，唯一非指数核心项）
速度 = 150 + 资质 / 4
```

映射依据：`sx.json` 中 6 个核心属性的 `calcType` 为「生命/物攻/物防/法攻/法防 = 指数，速度 = 乘法」；`基础核心属性` 表的 6 个数据行只用了 4 种 expression——指数×5（1 项）、指数×1（2 项）、指数×0.5（2 项）、线性（1 项）。唯一合理的对齐是：生命独占 ×5，物攻/物防共享 ×1，法攻/法防共享 ×0.5，速度落在线性。

**资质来源（本阶段确证）**：上述 4 个公式变体在编译代码里统一读 `ExpObject(人物编号, 3, 1)`，索引 `3` = **体**（`sx.json` id 3 = 体；装备函数 14..23 连续读 `ExpObject(人物编号, N, 1)` = sx id N，验证该索引即 sx 属性编号）。故 6 项核心属性**全部以体推导**，公式里的 `资质` 实为 `体`（constitution）。此前「物攻=勇、法攻=智、法防=精、速度=敏」为语义假设，与源码不符。

### 3.3 职业属性系数 function

```js
系数 = round100(
  (clamp(人物资质系数, 1, ∞) - 1) × (职业系数 / 10)
  + 职业基础系数
)
```

职业不是简单加点，而是独立百分比系数，最终面板乘它。

### 3.4 特定属性统计 function（面板结算）

```js
面板 = 基础属性 × (100 + 各类加成) / 100 × 职业系数
```

## 5. 资质 → 核心属性映射（本阶段已确证）

`_core_formula.pretty.json` 里「基础核心属性function」表有 6 行，每行是「属性编号 → 公式分支」：

| 属性编号 | 公式分支 | 公式形态 | 对应核心属性 |
|---|---|---|---|
| 55 | 1026 | 指数 ×5 | 生命 |
| 83 | 1027 | 线性 `150 + 体/4` | 速度 |
| 85 / 33 | 1028 | 指数 ×1 | 物攻 / 物防 |
| 36 / 35 | 1029 | 指数 ×0.5 | 法攻 / 法防 |

| 核心属性 | 公式形态 | 资质来源 |
|---|---|---|
| 生命 | 指数 ×5 | 体 |
| 速度 | 线性 `150 + 体/4` | 体 |
| 物攻 | 指数 ×1 | 体 |
| 物防 | 指数 ×1 | 体 |
| 法攻 | 指数 ×0.5 | 体 |
| 法防 | 指数 ×0.5 | 体 |

> **证据分级**：**公式形式与常数（底数 1.0095、指数 ×10、线性 ÷4）是源码铁证**；**资质来源统一为体**由「基础核心属性function」的 4 个公式变体全部读 `ExpObject(人物编号, 3, 1)`（索引 3 = 体）锁定。上表「属性编号」55/83/85/36/33/35 是 C3 内部核心属性标识，**非** `sx.json` id（核心属性的 sx id 是 6-11）；物攻/物防与法攻/法防两两共享同一公式，编号先后不影响数值。

## 6. 与蛋蛋江湖 2.0 此前实现的差异

| 属性 | 旧实现（线性自创） | 原版（指数 / 线性，均以体推导） |
|---|---|---|
| 生命 | `100 + 体×15 + 精×4` | `5 × (100 + 1.0095^(体×10) × 5)` |
| 物攻 | `20 + 勇×4 + 敏` | `100 + 1.0095^(体×10) × 5` |
| 物防 | `10 + 体×2.5 + 勇` | `100 + 1.0095^(体×10) × 5` |
| 法攻 | `20 + 智×4 + 精` | `0.5 × (100 + 1.0095^(体×10) × 5)` |
| 法防 | `10 + 精×2.5 + 智` | `0.5 × (100 + 1.0095^(体×10) × 5)` |
| 速度 | `20 + 敏×6` | `150 + 体/4` |

指数底数 `1.0095` 意味着资质从 10 涨到 20 时，`1.0095^100 → 1.0095^200 ≈ 6.6`，面板指数放大；线性公式只有线性增长。这是旧白板号面板与原版「数值体系本身不对」的根因。

## 7. 落地要点

1. 白板资质改回 `10/10/10/10/10`（铁证）。
2. 面板公式换成指数模板，核心常数：底数 `1.0095`、指数 `资质 × 10`、天资除数 `15`。**6 项核心属性（生命/速度/物攻/物防/法攻/法防）均以体推导**：生命取系数 5，物攻/物防取系数 1，法攻/法防取系数 0.5。
3. 速度 = 线性 `150 + 体/4`（本阶段已确证）：`基础核心属性function` 唯一非指数项，读 `ExpObject(人物编号, 3, 1)`（索引 3 = 体）。白板号体=10 → 152.5。

## 8. 附加属性 · 暴击几率 / 暴击伤害（本阶段新增，证据等级 A）

### 8.1 白板号面板观测值（空白存档实测）

| 属性 | sx id | 白板号面板 | 蛋蛋旧实现 | 偏差 |
|---|---|---|---:|---|
| 暴击几率 | 12 | **5%** | `智×0.006 + 敏×0.004` → 10% | 高 5pp |
| 暴击伤害 | 13 | **150%**（= 1.5 倍） | `(1.5−1)×100` → 50% | 低 100pp |

### 8.2 战斗结算源码（c3runtime.js，铁证）

```js
// 58077「暴击计算function」：暴击几率 = clamp(sx12 值, 0, 100)，属性值即百分数
() => C3.clamp(n0.ExpObject(12, 人物, 0), 0, 100)
// 58083「不暴击」= 100 − 暴击几率
// 57793：暴击伤害系数 = clamp(sx13 值 / 100, 0, ∞)
() => C3.clamp(divide(n0.ExpObject(13, 人物, 0), 100), 0, Infinity)
```

**关键结论**：暴击伤害系数 = `sx13 / 100`，**不是** `1 + sx13/100`。sx13 是「暴击伤害总量百分比」：白板 150 → 系数 1.5（暴击造成 1.5 倍伤害）。此前「1.5 倍 = 增量 +50%」的增量语义是蛋蛋自造，与原版总量语义不同。

### 8.3 面板显示源码（特定属性统计function，data.json 事件表）

```
特定属性统计(人物, 属性12=暴击几率) = 角色初始天资(12) + 天命天资(12) + 装备总属性(12)
```

- 属性 12 走「初始天资 + 天命 + 装备」分支，**无资质/等级推导项** → 暴击几率不随资质成长，白板恒 5%，靠天命/装备堆叠。
- 属性 13 不在特判分支，走默认（装备/技能/命石/命格/副官/幻化/灵兽/神位总和）；白板 150 是角色面板基础值（战斗直接读 sx13）。

### 8.4 sx.json 默认值 ≠ 白板面板值

`sx.json`：暴击几率 default=6、暴击伤害 default=40。该 default 是**属性表/词条基准**，不是角色初始面板值。角色面板值由「角色初始天资 + 养成」推导，白板主角 = 5% / 150%（`角色初始天资(12)` 的实现表达式在 c3runtime 编译中重编号，未逐字还原，白板观测值为权威口径）。

### 8.5 蛋蛋落地对照

| 环节 | 旧实现 | 新实现（对齐原版） |
|---|---|---|
| 白板暴击几率 | `智×0.006 + 敏×0.004` → 10% | 固定 `0.05`（5%），资质无关，装备「会心」词条继续累加 |
| sx13 存储 | `(1.5−1)×100 = 50`（增量） | `1.5×100 = 150`（总量百分比） |
| 战斗暴击系数 | `1 + sx13/100` | `sx13/100`（c3runtime 57793 形态） |
| 暴击伤害倍率 | 1.5（数值等价） | 1.5（150/100） |

> 白板号代入：暴击几率 5%、暴击伤害 150%（系数 1.5），与空白存档面板完全一致。

## 9. 命中 / 闪避 / 技能冷却（第一梯队，证据等级 A）

### 9.1 命中/闪避公式（闪避计算function，c3runtime 58097/58105）

原版命中不是「基础 30% ± 修正差」，而是**比率式**：

```js
// 58097「不闪避」（= 命中率）：
C3.clamp(97 × (100 + 命中修正) / (100 + 闪避修正), 下限, 100)
// 58105「闪避率」：
100 − 命中率
```

- `命中修正` = 攻击方 sx18，`闪避修正` = 目标方 sx19。
- **下限 30** = data.json 事件表常量「最低真实命中率」（证据 A）；上限 100。
- **白板**（命中修正 = 闪避修正 = 0）：命中率 `97 × 100/100 = 97%`、闪避率 3%。修正相等时在公式中相互抵消，恒 97%。

> 蛋蛋旧实现 `evadeRate = clamp(0.3 + (闪避−命中)/100, 0, 0.95)` + `命中保底 5%` 是自创差值式，白板闪避 30%、命中 70%，与原版 97%/3% 严重不符。

### 9.2 命中/闪避修正白板值（sx18/19 = 0）

- sx18/19 不在「特定属性统计function」任何特判分支（3/12/14/66/48、核心 id 等），走默认分支（装备/技能/命石/命格/副官/幻化/灵兽/神位总和）→ **白板无固有基础 = 0**。
- sx18/19 不进「全局数据载入」（不像暴击 12/13/14 需要存档），为实时计算属性。
- `sx.json` 的 default 5 是词条基准（装备「命中的/闪避的」词条），非面板值。

### 9.3 技能冷却（sx37）

```js
// c3runtime 55319：技能冷却时间 = 基础CD × (100 − 技能冷却) / 100
round(10 × ExpObject(技能, 20) × clamp(100 − ExpObject(37, 角色, 0), 下限, 100) / 100) / 10
```

- sx37 = 「技能冷却缩减 %」，系数 = `(100 − sx37)/100`。
- **白板 sx37 = 0 → 系数 1（满 CD）**。蛋蛋 `cooldownRate` 白板 0 已正确，无需改值（仅成长来源待接）。
- data.json 同段「技能冷却最低值 = 5」「减伤词条数值上限 = 80」（印证 sx 减伤 cap 80）。

### 9.4 蛋蛋落地对照

| 环节 | 旧实现 | 新实现（对齐原版） |
|---|---|---|
| 命中率公式 | `1 − clamp(0.3 + (闪避−命中)/100, 0, 0.95)` | `clamp(97×(100+命中)/(100+闪避), 30, 100)/100` |
| 白板命中率 | ~70% | **97%** |
| 白板闪避率 | ~30% | **3%** |
| 命中/闪避修正白板 | 8% / 10%（资质公式） | **0 / 0**（资质无关，走装备词条） |
| 技能冷却 | 白板 0（正确） | 白板 0（保持） |

> 白板号代入：命中率 97%、闪避率 3%；命中修正/闪避修正面板 0%。

## 10. 18 乘区白板输入（第二梯队，证据等级 A）

蛋蛋 `damage.ts` 的 18 乘区公式已逐项对齐 c3runtime 57755-57920（增伤 `(100+sx)/100`、减伤 `(100−sx)/100`、受伤害 `(100+sx)/100`）。**这些乘区属性（sx20-27、44-59、118-120）走「特定属性统计function」默认分支（养成总和），白板无固有基础 = 0** → 白板乘区恒 1（无加成）。`sx.json` 的 default（增伤 20、减伤 8、最终增伤 10、受伤害 25 等）是词条基准，非面板值；「受所有伤害 25」若作白板则白板角色受伤 ×1.25，不合理。

> 结论：18 乘区白板输入 = 0 已正确，蛋蛋无需补基础值。增伤/减伤等靠装备词条（蛋蛋已提供 sx20-27 词条）与技能堆叠。
