# 13 世界普通战斗掉落纠正

核对日期：2026-09-09。来源为相邻 `诸天刷宝录/_analysis` 中的原版数据与 Construct 3 事件树，不以本项目旧测试推导规则。

## 范围与结论

完整核对 13 个普通世界、130 个小关、260 种敌人的 `dl` 专属掉落表。共 431 种物品：428 种装备、秘境门票（5）、介绍信（6）、副本门票（7）。另有矿石、木材、草药、精华四类地点材料。

原实现从整关合并装备池中固定抽取 1～2 件（精英 1～2 件），没有执行材料与票券入库，导致收集悬榜不能完成。现改为按敌人逐项判定，并在同一击杀中分别结算两个地点材料槽。

本次范围是这 13 世界的普通推图与驻守战斗掉落。大型副本、秘境、异界等独立玩法的全部状态机不在本次核对范围内；普通战斗掉落它们的门票不等于这些玩法已全面对齐。

## 原版事件证据

`campaign-loot-runtime.json` 保存现有事件解码器提取的表达式、action SID、节点路径和调用参数；可在原始 `data.json` 中按 SID 定位，并对照 `scripts/c3runtime.js` 的表达式编号复查。

- `核心阵亡` 的普通“战斗”分支调用一次 `掉落计算`，参数包括原敌人编号、品级、难度与位面。
- `掉落计算function`（事件 1547）遍历 `dl` 的对应敌人列，每个有效物品单独抽取，概率为 `clamp(wp[item,32] × (100 + 总掉落率加成) / 100, 0, 10000) / 10000`。普通装备与套装不互相替换；有可能无装备掉落，也可能同次多件。
- 普通装备按 `普通装备随机品质function` 权重生成，再加 `wm[world,20]`；本轮核实 13 世界该值均为 1。套装沿用其固定品质与现有原版装等／词条生成。
- 特殊物品 5、6、7 在普通战斗分支按各自表项掉率掉落，每次 1 个；本轮原表均为 500/10000。
- `sq[location,10]` 和 `[11]` 是两个材料类别槽。各槽分别判定，基础概率为 `wm[world,23 + family×2] / 2 / 100`，再乘 `(100 + 总掉落率加成) / 100` 并限制在 0～1。
- 材料品质为 `wm[world,22 + family×2] + 材料随机品质(敌人品级)`，按 `wp` 的类别、家族、品质精确查找，每次获得 1 个。本轮所有普通世界基础材料品质均为 1，难度数不直接抬升该品质。因此普通战斗只产出各家族 1～4 品材料，不能因定义表包含 5～9 品就把它们加入普通掉落。
- `总掉落率加成function`（事件 1601）合计当前队伍的 sx42，并加科技 65 效果 ×100，保留两位小数。实现复用当前装备属性计算与原版城市科技效果函数；科技 65 每级增加 1.5 个百分点。sx 表中的词条默认值不当作每人固有加成。

| 敌人品级 | 材料额外品质 0 | +1 | +2 | +3 |
| --- | ---: | ---: | ---: | ---: |
| 普通 | 90% | 10% | 0 | 0 |
| 精英 | 50% | 40% | 10% | 0 |
| 头目 | 0 | 70% | 30% | 0 |
| 首领 | 0 | 0 | 70% | 30% |

例如黄巾起义的两个材料槽是矿石与木材：零加成时各自有 37%、28% 概率掉 1 个，普通敌人的矿石可能为初晶矿石或灵耀矿砂。首领的材料品质更高，所以刷初晶矿石不能只看首领掉落。

## 全量目录与复核

`campaign-loot-table.json` 列出全部 130 小关、每关 6 个敌人引用、每项物品名称／概率、两个材料槽及源文件 SHA-256。生成后的运行时数据在 `src/content/campaign-loot.generated.ts`。

在 `egg-jianghu` 下运行：

```powershell
npm run evidence:loot:check
```

该命令重新读取原始 sq/wm/wp/dl 表，逐项比较生成文件及含源码指纹的证据目录。原版客户端改变时须同时重新核查上述运行时公式。

## 存档与验证

材料与票券复用 `state.materials` 的原版物品 ID 键。保留既有装备与材料；不为历史击杀猜测补发掉落。装备仍受现有 300 格限制，堆叠材料沿用本项目独立库存，装备满包也继续结算后续材料／票券。

全量入库测试遍历全部 130×6 个敌人引用，用提高科技掉率至概率上限的测试夹具检查每个专属表项及材料槽。另用零加成的固定随机种子验证自然空掉落、材料、票券及品质边界，不把强制概率测试当作自然掉率证据。

收集任务回归通过真实 `settleCombatEvent` 取得材料，验证存读档、数量扣除和禁止重复领取。Playwright 用独立测试存档验证两种矿石的揭榜、击杀结算、页面可领取状态及保存后的扣除量；截图保存于 `test-results/campaign-loot-*`。浏览器测试使用现有击杀调试入口，并非手工挂机时长或原客户端实机掉率统计。
