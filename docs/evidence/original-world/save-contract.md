# 势力、城镇与城市经营存档契约

- 状态：阶段 0 已确认边界
- 目标版本：18
- 目标 save key：`egg-jianghu-2-save-v18`
- 兼容策略：不迁移、不覆盖 v17

## 总体原则

- v18 使用新 key 创建新档；v17 旧档只做存在性提示，不参与 v18 加载。
- 删除 v18 存档不得删除 v17 或更早版本存档。
- 只保存不可无损重建的权威状态；名称、文案、公式结果和总览统计从内容定义与权威状态派生。
- 势力使用现有稳定内部 ID；原版数字 ID 保存在内容定义的 `sourceId`，不另存一份可漂移映射。
- 城市实体以原版 `sourceId` 的稳定字符串形式作为持久化键。
- UI 选择、弹窗、分页、筛选、hover 和动画状态不进入存档。
- 运行中队列只保存剩余时长，不保存可用于离线补算的系统时间戳。

## 顶层边界

v18 保留当前战斗、侠客、装备、物品、位面和高阶系统状态，并新增以下权威分区：

```text
GameStateV18
├─ 当前 v17 权威状态
├─ factionReputation
├─ unlockedSceneIds
└─ city
   ├─ map
   ├─ company
   ├─ technology
   ├─ resources
   ├─ facilities
   ├─ dispatches
   └─ ledger
```

具体 TypeScript 类型在进入业务实现时定义，但不得突破本文件的所有权和派生规则。

## 势力与城镇

### 必须持久化

- 每个势力的贡献余额。
- 每个正式势力的声望值；声望等级由原版公式派生。
- 已解锁势力 ID。
- 已解锁且不能从位面进度无损重建的场景 ID。
- 每个势力当前悬榜及其剩余刷新时间。
- 已接受任务的目标、进度和领取状态。
- 已招募侠客和已学习技能继续归现有侠客进度所有。

### 不应重复持久化

- 势力名称、介绍、六个技能 ID、城镇 ID和场所功能。
- 位面主城、公共场所与正式势力城镇的静态关系。
- 可由当前位面解锁和势力解锁直接派生的场景可见性。
- 势力页和城镇页分别维护的功能副本。

## 城市地图

### 必须持久化

- 当前城市尺寸或扩建阶段。
- 已购买地块。
- 每个地块的地面类型。
- 每个地块的建筑、建筑等级和运行状态。
- 在建、拆除或迁移项目的输入保留、剩余时间和目标地块。

### 必须派生

- 城市总属性、发展度和建筑分类统计，除非运行时证据证明原版存在不可重建增量。
- 地价、租金、建造费用和迁移费用。
- 建筑显示名称、介绍、图片和功能入口。

## 公司

### 必须持久化

- 是否已注册及玩家输入的公司名称。
- 原版要求保存的现金与经营资源余额。
- 职位到侠客 ID 的任命关系。
- 无法从地块与建筑重建的公司资产状态。
- 已结算收支流水的最小必要记录；历史展示数量设置固定上限，禁止无限增长。

### 必须派生

- 总资产、总租金、建筑数量、土地数量和职位加成。
- 由地块、建筑、任命与角色能力共同计算的总览值。

## 科技与产业设施

### 必须持久化

- 科技的解锁或等级状态。
- 设施的材料池和原版定义的容量状态。
- 生产、科研、建造、锻造、合成、展览、修习、驯养和教育队列。
- 队列输入物、执行角色、剩余时长和原版要求预先确定的结果参数。
- 分队派遣编组、目标、剩余时长和待领取产出。

### 队列约束

- 每种队列使用明确的 discriminated union，禁止把不同设施状态塞进无约束字典。
- 开始队列时原子扣除或保留输入；失败不得留下半扣资源。
- 完成队列时原子写入产出并清空队列。
- 取消、材料返还和队列容量必须逐项服从原版证据。
- 存档载入后恢复 `remainingMs`，离线期间不减少。

## 资源所有权

- 位面货币继续归 `worldCurrency`。
- 势力贡献继续归 `contribution`。
- 势力声望使用独立 wallet，不与贡献互换存储。
- 现世现金与建筑资源进入 `city.resources`；已有全局资源只有在原版确实共用时才复用。
- 装备、材料、侠客和灵兽继续由各自现有权威容器持有；城市设施只保存引用与队列输入保留。
- UI 不得直接修改 wallet、背包、侠客或队列。

## 时间与保存

- 运行时使用统一单调时钟推进势力刷新与城市队列。
- 后台标签恢复时可补仍在运行期间真实经过的时间；关闭游戏期间不补算。
- 每次资源变化、队列开始或完成、建造状态变化、任命变化后立即保存。
- 多标签或外部写入继续使用 expected snapshot 检测，冲突时拒绝覆盖。
- 损坏档不得静默覆盖原字符串。

## 进入业务实现前的冻结条件

- [ ] 所有新增资源都有唯一权威容器。
- [ ] 所有新增队列都有明确输入、输出、取消和完成状态。
- [ ] 所有派生字段均能从权威状态和原版公式重算。
- [ ] 原版证明必须保存但本契约遗漏的字段已补入。
- [ ] `GameStateV18`、初始状态、校验器和 save key 在同一提交内完成。
- [ ] v17 存在性提示、v18 删除范围和坏档保护有测试。
