# 侠客名册与武功配置改版设计

## 背景

当前“侠客”Tab 同时承担以下职责：

- 使用银两购买未拥有侠客；
- 在“藏经阁 · 五门武学”中解锁武功；
- 为每位侠客从全局武学中选择一门武功；
- 在侠客卡片中培养该武功。

这些职责与新的角色、武功规则冲突。侠客和武功的获取方式将在后续独立设计，武功也不在侠客页学习或进阶。新的侠客页只负责管理已拥有侠客及其现有武功配置。

## 目标

- 侠客页只显示已拥有侠客，不显示未拥有侠客、剪影或购买入口。
- 移除“藏经阁 · 五门武学”、武功参悟、学习、进阶和突破入口。
- 每位侠客最多学习 20 门武功，最多装备 4 门武功。
- 全部已学武功的被动效果持续生效并允许叠加，是否装备不影响被动。
- 只有 4 个装备槽中的武功能够在战斗中施展主动招式。
- 装备槽顺序决定主动武功的施展优先级。
- 允许遗忘武功，并返还该侠客在这门武功上累计培养投入的 80%。
- 兼容现有存档，将旧的单武功配置迁移到新结构。

## 非目标

- 本次不设计侠客的获取方式。
- 本次不设计武功的获取、学习、进阶或突破页面。
- 本次不扩展完整武功库、掉落来源或长期数值平衡。
- 本次不新增装备强化、职业进阶等与武功配置无关的系统。

## 页面结构

页面参考 `docs/挂机游戏研究C.html` 中“侠客阵容”的布局，采用“左侧紧凑名册 + 右侧详情工作台”。

### 左侧侠客名册

- 桌面端使用约 340px 宽的侧栏，并以三列紧凑卡片展示侠客。
- 只渲染已拥有侠客。
- 每张卡片展示头像、姓名、等级、门派或定位，以及“出战中”状态。
- 当前选中侠客使用明显的金色描边和辉光。
- 出战侠客排在前面，其余侠客按等级降序排列；相同等级保持稳定顺序。
- 首次进入页面时优先选中当前出战队伍第一位侠客；若该侠客不可用，则选择名册中的第一位。
- 窄屏下名册移动到详情上方，并增加横向可容纳的卡片数量，详情区域改为纵向布局。

### 右侧侠客详情

详情头部展示：

- 头像、姓名、等级、门派、五行和刚柔属性；
- 攻击、防御、气血、战力及五行相性说明；
- 侠客天赋；
- 现有的侠客“提升境界”入口及所需资源。

详情主体依次展示：

1. 已学武功数量、已装备数量及所有已学武功的被动汇总。
2. 4 个出战武功槽位。
3. 最多 20 门已学武功列表。

页面不出现购买侠客、藏经阁、学习武功、武功升级、武功进阶或残页突破入口。

## 武功装备区

- 固定显示 4 个槽位，允许存在空槽。
- 槽位编号 1 到 4 即施展优先级。
- 已装备卡片展示武功名称、主动类型、冷却、当前重数及被动摘要。
- 每个已装备武功提供“提高优先级”“降低优先级”和“卸下”操作。
- 优先级调整通过交换相邻槽位完成，允许与空槽交换。
- 从已学列表点击“装备”时，将武功放入编号最小的空槽。
- 4 个槽位已满时拒绝装备并提示先卸下一门。
- 同一门武功不能重复装备。

## 已学武功区

- 标题显示当前数量，例如“已学武功 7/20”。
- 每行展示武功名称、类型、当前重数、主动效果摘要、被动效果及装备状态。
- 每门已学武功都提供“遗忘”操作；已装备武功确认遗忘后会自动卸下。
- 未装备武功额外提供“装备”操作；已装备武功显示其槽位优先级，不提供重复装备操作。
- 此区域不提供学习、升级、进阶或突破操作。
- 当武功数量接近 20 时仍使用单列列表；20 行规模无需额外分页。

## 数据模型

每位侠客的进度从“单一装备武功”改为“已学武功账本 + 四槽配置”。概念结构如下：

```ts
interface ResourceInvestment {
  silver: number
  experience: number
  pages: number
  reputation: number
}

interface LearnedMartialProgress {
  rank: number
  invested: ResourceInvestment
}

interface HeroProgress {
  unlocked: boolean
  level: number
  learnedMartials: Record<string, LearnedMartialProgress>
  equippedMartialIds: [string | null, string | null, string | null, string | null]
}
```

约束如下：

- `learnedMartials` 最多包含 20 个有效武功 ID。
- `equippedMartialIds` 只能引用 `learnedMartials` 中的武功。
- `equippedMartialIds` 中不能出现重复武功 ID。
- `invested` 记录该侠客在对应武功上的实际累计培养投入，不按当前价格反向计算。
- 账号级的 `unlockedMartials` 暂时保留，供未来武功获取与学习系统使用，但侠客页不再直接操作它。

每门武功定义增加单一、可计算的被动效果：

| 武功 | 被动效果（每重） |
| --- | --- |
| 沧浪降龙掌 | 攻击 +3% |
| 凝霜十三剑 | 防御 +3% |
| 太极吐纳法 | 气血上限 +4% |
| 金刚伏魔棍 | 攻击 +4% |
| 厚土归元功 | 防御 +4% |

被动百分比先按效果类型和武功重数求和，再统一乘到等级成长后的攻击、防御或气血上，避免因计算顺序产生差异。装备状态不参与被动是否生效的判断。

## 遗忘武功

点击“遗忘”后先打开二次确认弹窗，弹窗必须展示：

- 武功名称和当前重数；
- 遗忘后消失的被动效果；
- 如果武功已装备，将自动从对应槽位卸下；
- 银两、阅历、残页和声望分别返还多少。

退款按各资源独立计算：

```ts
refund = Math.floor(invested * 0.8)
```

确认后按以下顺序执行：

1. 返还各项资源。
2. 从 `learnedMartials` 删除该武功。
3. 将所有引用该武功的装备槽设为 `null`。
4. 移除该武功对应的战斗冷却状态。
5. 重新计算侠客属性、被动汇总和队伍战力。
6. 保存游戏并显示成功提示。

其他装备槽保持原位置，不因遗忘自动前移。取消弹窗不得改变任何状态。

## 战斗规则

侠客每次行动时按槽位 1 到 4 检查已装备武功：

1. 跳过空槽和仍在冷却中的武功。
2. 施展第一门冷却完毕的武功。
3. 如果没有可施展武功，则执行普通攻击。

每门武功独立计算冷却，冷却状态按侠客 ID 和武功 ID 保存：

- 调整槽位顺序不重置冷却。
- 卸下后再次装备，仍沿用本场战斗中该武功已有的冷却。
- 本场战斗首次装备的新武功从完整冷却开始，防止通过换装立即释放高冷却武功。
- 遗忘武功会清除它在本场战斗中的冷却记录。
- 新战斗创建时，初始装备的 4 门武功都从冷却完毕状态开始。

挂机战斗中允许装备、卸下和调整顺序，修改从该侠客下一次行动开始生效。BOSS 挑战或秘境战斗中沿用现有养成锁定，装备、排序、卸下和遗忘操作均禁用，并显示具体原因。

## 旧存档迁移

载入旧存档时执行幂等归一化：

- 将旧的 `martialRanks` 中所有有效武功转为 `learnedMartials`。
- 如果旧的 `equippedMartialId` 不在 `martialRanks` 中，也将其补入已学武功。
- 将旧的 `equippedMartialId` 放入第 1 槽，其余槽位设为 `null`。
- 根据旧武功重数和历史培养公式计算已发生的培养投入：一重为 0；二重为 55 银两和 12 残页；三重为 165 银两和 36 残页。
- 一重武功没有既有培养投入时，其迁移账本为零，不返还账号级解锁武功所消耗的资源。
- 过滤不存在的武功 ID、重复装备和越界槽位，并保证迁移可重复执行而不重复记账。
- 账号级 `unlockedMartials` 保持不变。

迁移后立即按新结构保存，后续载入不再重复迁移。

## 错误处理

- 未拥有侠客不得成为详情页选中对象。
- 装备未学习、无效或重复的武功时返回明确提示，不修改状态。
- 已装备 4 门武功时拒绝新增装备。
- 已学武功达到 20 门时，由未来的学习入口拒绝继续学习；侠客页只显示上限状态。
- 资源账本中的负数或非有限值在载入时归零。
- 遗忘退款按当前账本余额计算，任何资源都不得因退款变为负数。
- 养成锁定期间所有相关按钮同时禁用，业务函数也执行相同校验，避免绕过 UI。

## 验证

### 单元测试

- 新档为已拥有侠客生成有效的已学武功和四槽配置。
- 旧存档可迁移，迁移重复执行不会重复记账或退款。
- 已学 20 门和已装备 4 门的上限均有效。
- 装备、卸下、相邻交换和空槽交换符合预期。
- 同一武功不能重复装备，未学习武功不能装备。
- 全部已学武功被动叠加，卸下不影响被动，遗忘后被动消失。
- 遗忘按每项累计投入的 80% 向下取整退款，并清除学习、装备和冷却状态。
- 战斗按槽位顺序选择第一门冷却完毕的武功，无可用武功时普通攻击。
- 调整优先级不重置冷却，新装备武功从完整冷却开始。
- BOSS 挑战和秘境战斗中的配置操作被拒绝。

### E2E 测试

- 侠客页只渲染已拥有侠客。
- 页面不存在侠客购买、“藏经阁 · 五门武学”、武功学习和武功进阶入口。
- 点击左侧侠客卡片会更新右侧详情。
- 四个槽位始终可见，装备、排序和卸下反馈正确。
- 遗忘弹窗展示 80% 退款明细；取消不改状态，确认后数量、资源和被动均更新。
- 窄屏下名册与详情改为上下布局，核心操作仍可见可用。

## 完成标准

- 页面结构与确认的参考布局一致。
- 新武功数据结构、存档迁移、被动叠加、四槽战斗规则和遗忘退款均真实生效，不是静态占位展示。
- 现有挂机、BOSS、秘境、存档导入导出和侠客升级功能无回归。
- TypeScript 构建、单元测试和 E2E 测试全部通过。
