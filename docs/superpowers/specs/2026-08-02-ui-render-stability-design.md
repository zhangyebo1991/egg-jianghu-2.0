# 蛋蛋江湖 2.0 UI 增量渲染稳定性设计

## 背景与根因

当前 `src/main.ts` 每隔 `100ms` 推进战斗和任务运行时，随后无条件调用 `render()`。`render()` 使用 `app.innerHTML = renderShell(...)` 重建整个应用 DOM，即使生成的 HTML 没有变化也会替换所有按钮。

浏览器诊断中，【江湖】按钮在 `600ms` 内被替换 7 次。被替换的节点会丢失 `:hover`、`:active`、focus 和鼠标按下目标，因此用户会看到边框快速闪烁，并可能在按下与松开之间丢失点击。

该回归由 version 10 UI 切换时引入的 `100ms` 全量渲染放大，不是按钮配色、显卡或鼠标硬件问题。

## 目标

- 保留固定 `100ms` 战斗模拟和实时画面刷新。
- 相同语义的按钮、输入框、页签和容器在连续渲染间保持 DOM 节点身份。
- HTML 完全相同时跳过 DOM 操作。
- 页面切换、列表增删、战斗开始/结束时仍正确更新结构。
- 不引入新的运行时依赖，不改变玩法、存档或视觉样式。

## 方案

新增 `src/ui/dom-patch.ts`，提供一个应用根节点增量更新入口。`main.ts` 仍然通过现有纯 renderer 生成完整 HTML，但不再直接写入 `innerHTML`。

渲染流程如下：

1. `render()` 生成下一帧完整 HTML。
2. 如果 HTML 与上一帧完全相同，直接返回。
3. 首次渲染时正常创建 DOM。
4. 后续渲染把新 HTML 解析到离线 `template`，再递归同步到现有 DOM。
5. 节点类型或元素 tag 不兼容时才替换该局部节点；兼容节点只同步属性、文本和子节点。

### 节点匹配

同一父节点下优先使用稳定 key 匹配：

1. `id`
2. `data-testid`
3. `data-tab`
4. `data-action` 与关联的 `data-*` 业务标识组合

没有稳定 key 的展示节点按 tag 和相对位置匹配。key 不同的交互节点不得复用，避免列表变化后把鼠标按下的按钮悄悄变成另一项操作。

### 节点同步

- 增删变化的 attributes，同时保留同语义元素实例。
- 文本节点只更新 `nodeValue`。
- 子节点支持插入、移动和删除。
- `input`、`select`、`option` 的 `value`、`checked`、`selected` 属性与 DOM property 保持一致。
- 当前获得焦点且语义 key 未变化的控件保持 focus，不重置用户正在进行的交互。

应用现有 click/change 事件委托仍绑定在 `#app`，无需为新节点重新绑定 handler。

## 异常与边界

- 新旧根节点不兼容时，只替换应用根子树，不影响根外 toast。
- 页面切换允许替换 `<main>` 内不兼容的页面结构，但顶部 shell 和页签必须保持稳定。
- 战斗单位死亡、装备入包、任务刷新等列表变化必须通过 key 正确插入或删除，不能复用成错误业务项。
- 增量同步抛出异常时不得静默留下半更新页面；开发阶段测试应覆盖主要结构变化。

## 测试设计

先在 Playwright 写失败回归测试：

- 捕获【江湖】或【侠客】按钮实例，等待多个 `100ms` tick，断言查询到的仍是同一个节点。
- 鼠标按下按钮后等待超过一个 tick 再松开，断言页签仍成功切换。
- 战斗运行期间重复上述测试，确保动态内容变化不会替换页签和战斗控制按钮。

修复后执行：

- `npm test`
- `npm run build`
- `npm run test:e2e`
- `git diff --check`
- `codegraph sync ..` 与 `codegraph status ..`

浏览器验收覆盖桌面与 `390×844`：检查页面身份、空白页、错误 overlay、console error/warn、hover 边框稳定、慢速点击成功和截图证据。

## 非目标

- 不调整按钮颜色、边框动画或布局。
- 不降低战斗 tick，也不暂停鼠标悬停期间的战斗画面。
- 不重构现有领域状态或 renderer 输出格式。
