# 挂机战斗快速返回设计

## 背景

玩家点击小关卡后会进入自动挂机战斗。当前战斗由全局定时器持续推进，切换到侠客、队伍、BOSS 或秘境页面不会真正停止战斗；问题在于再次点击“关卡”时，界面会重置到大关卡列表，玩家无法直接返回正在进行的挂机战斗画面。

## 目标

- 小关卡挂机进行期间，在其他页面提供明确、随时可用的返回入口。
- 返回时继续展示原有战斗，不重新开战，不重置血量、回合、日志或奖励进度。
- 不改变战斗推进机制、存档格式和其他战斗模式的导航行为。

## 非目标

- 不为 BOSS 挑战或秘境战斗增加悬浮返回入口。
- 不增加暂停、停止、切换关卡或领取收益操作。
- 不引入 URL 路由、导航历史或新的持久化字段。

## 方案

采用从现有 `state.combat` 派生全局悬浮入口的方式。

显示条件同时满足：

- `state.combat.mode === 'idle'`
- `state.combat.status === 'fighting'`
- 当前没有显示该挂机战斗画面

悬浮入口由全局 `render()` 负责渲染，与 Header、Nav、Main 同级。它不保存独立的可见状态，避免 UI 状态与实际战斗状态不同步。

## 界面与交互

- 桌面端固定在页面右下角。
- 移动端贴近底部安全区，并避开底部导航和主要操作区域。
- 内容包括战斗中状态点、当前大关卡和小关卡，例如“青石古道 · 第 1 关”，以及“返回战斗”提示。
- 整个悬浮条均可点击，并使用语义化 `button`。
- 提供明确的 hover、active 和键盘 focus 样式。
- 提供包含关卡信息的 `aria-label`，保证辅助技术能够识别入口用途。
- 当前已经处于挂机战斗画面时隐藏入口，避免重复操作。

## 数据流

1. 小关卡挂机通过现有 `startIdleStage()` 创建并启动战斗。
2. 用户切换到其他 Tab，`activeTab` 改变，但 `state.combat` 保持不变。
3. 全局定时器继续调用 `stepCombat(state)`，推进回合并发放在线战斗奖励。
4. `render()` 根据当前战斗状态和页面状态决定是否输出悬浮入口。
5. 用户点击悬浮入口时，事件处理器重新检查挂机战斗是否仍在进行。
6. 检查通过后设置 `activeTab = 'idle'`、`chapterRegionId = state.combat.regionId` 和 `levelView = 'combat'`，然后重新渲染。
7. 重新渲染后显示原战斗画面，悬浮入口因当前已在战斗画面而自动隐藏。

## 边界与异常处理

- 若点击发生前战斗状态已经变化，事件处理器不进入失效的战斗画面。
- 挂机战斗结束、存档重置、导入存档或切换为其他战斗模式后，悬浮入口在下一次渲染时自动消失。
- 入口不调用 `startIdleStage()`，因此不会重建敌人或清空现有进度。
- 原有 `setInterval`、`stepCombat()`、自动保存和页面卸载保存逻辑保持不变。

- `egg-jianghu/src/style.css`

## 验证

- 开始小关卡挂机，切换到侠客页后悬浮入口可见。
- 在其他页面停留或推进测试时间后，战斗回合或统计继续变化。
- 点击入口后返回同一大关卡、同一小关卡的当前战斗。
- 返回过程中敌方血量、回合和日志不被重置。
- 回到挂机战斗画面后悬浮入口隐藏。
- 未开始挂机时不显示悬浮入口。
- BOSS 战与秘境战斗进行时不显示悬浮入口。
- 桌面端和移动端均可见、可点击，且不遮挡主要导航。
- 运行现有单元测试、TypeScript 构建和 Playwright 端到端测试，确认无回归。

## 成功标准

玩家开始小关卡挂机后，可以自由浏览其他页面；战斗仍持续推进，并能通过右下角悬浮条一键返回原挂机战斗画面。
