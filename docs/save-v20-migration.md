# v20 存档进度迁移

## 范围与规则

- 新存档内容版本为 20；现有可读取的 v19 在继续游戏、导入或云校验时迁移。v18 及更早版本仍遵循原有不兼容边界，保留旧数据，不猜测改造城市、职业或装备结构。
- 用户选择按旧累计经验换算，不按击杀数或技能点估算：`累计经验 = 50 × 旧等级 × (旧等级 - 1) + 剩余经验`，再逐级扣除原版门槛 `round(10000 × 1.129^(等级 - 1) - 9000)`。旧档缺乏逐次经验历史，此结果是确定的经验守恒迁移，不代表对历史战斗收益的精确重放。
- 所有角色都换算；所有已解锁职业按各自等阶、等级和已有经验继续升级，满级上限沿用 10。当前职业不切换，已满级记录不重算。
- 检查三个装备方案；穿戴等级高于新角色等级的引用置空，装备实例保留在 inventory。满背包允许暂时超容，不删除、出售或复制装备，不触发卸装授予效果。
- v20 不再换算，导入、刷新和云端往返不会重复降级。资源、技能点、武学、装备实例、关卡等其他长期进度不由本迁移改动；既有加载归一化和离线蛋蛋结算照常执行。

## 本地保存与云存档

- 继续沿用 `egg-jianghu-2-save-v19` 物理槽位，实际版本由 JSON 的 `version` 判断。这保证旧页面的 storage 事件和快照冲突保护仍能发现新版写入，防止旧会话覆盖。
- 首次覆盖 v19 前，将原始字符串备份至 `egg-jianghu-before-v20-migration`。备份失败则停止写入，原档不变；新档写入失败可重试。删档不会恢复或覆盖这份备份。
- 继续游戏成功时立即写入 v20，避免下次重新从旧等级计算。
- 云服务同步打包同一 hydrate/validator。v19 上传输出 v20；已有云档下载经客户端导入迁移。发布不批量重写云数据库。
- 不能将不支持 v20 的旧版前端或云校验直接用于新版存档；回滚需保留 v20 兼容能力。数据库备份不自动覆盖上线后的用户进度。

- 单测覆盖经验边界、职业连续升级及非当前职业、全部装备方案、满背包、输入不变、重复迁移、备份／写入失败、陈旧会话冲突、非法经验、未知版本和云端往返。
- 浏览器验证桌面 1440 和手机 390 下继续、备份、等级／职业显示、刷新不重复迁移；同时回归开始／覆盖／删除／多标签页及云存档流程。
- 用户提供的真实存档离线试算：主角 99 → 19，剩余经验 25,522 → 61,645；两名队友 97 → 19，剩余经验均为 44,869。81 件装备实例保持一致，已穿戴装备全部满足新等级；三个白丁已满级保持不变。逐字段差异仅版本号及三名角色等级／经验。原文件不修改、不提交或上传服务器。
