# 原版装备图标提取与全界面替换

日期：2026-08-14
状态：设计已确认，已实现并验证

## 背景与目标

当前项目的装备图标仍以八个部位通用图标、背包线稿或“兵、甲、佩”等文字标识为主。不同装备即使名称、武器类型或套装归属不同，在背包和侠客页面中仍会显示相同的部位图标，无法像《诸天刷宝录》原版一样通过美术快速区分。

本阶段目标是从本机《诸天刷宝录》当前 `package.nw` 中确定性提取原版装备图标，将所有现有可掉落装备映射到对应原版美术，并覆盖项目中实际展示装备图标的全部界面。生成后的图标和映射作为正式项目资源提交，正常构建不得依赖本机原版目录。

该文件是可由 ZIP 读取器打开的 NW.js 包，包含本阶段需要的全部条目：

- `sq.json`

- `shili.json`
- `images/物品图标-sheet0.webp`
- `images/物品图标-sheet1.webp`
- `images/装备标识-sheet0.webp`

项目 `scripts/tmp/zhutian-pkg/data.json` 与当前 `package.nw/data.json` 的长度均为 `11194189` 字节，SHA256 均为：

`B615DD71DFE18D682F29E3666C069C5C1901BB73DC02EC794B4E0357DBDBF595`

原版 `_analysis` 中当前使用的 `wp/sq/dl/tz/zbct/shili` 六张表也逐一与包内条目哈希一致；但 `_analysis/data.json` 属于旧版本，不能继续作为图集坐标来源。

### 动画与装备映射

`data.json` 中 Construct 对象“物品图标”包含 530 个动画。动画名称与 `wp.json` 第 3 列的资源名称直接对应，例如：

- `wp_101` 长戟 → `中式古代长柄`
- `wp_257` 古剑 → `中式古代刀剑`
- `wp_386` 文卷 → `中式古代书卷`
- `wp_123` 物攻项链 → `中式古代物攻项链`

当前装备定义由 186 件普通装备和 260 件地点套装组成，共 446 件。全量核对结果：

- 成功映射：446/446
- 缺失映射：0
- 唯一美术资源：186
- 原始帧尺寸：全部 100×100
- 旋转帧：0
- 相关帧分布：`物品图标-sheet0` 364 次、`物品图标-sheet1` 66 次、`装备标识-sheet0` 16 次

原版允许多件装备共用同一动画。例如普通装备与多个具名套装项链可能共同使用 `中式古代物攻项链`。本项目应保留该复用关系，不为原版没有独立美术的装备虚构新图标。

### 体积实测

按现有怪物素材脚本相同的 Sharp WebP 参数 `quality: 82` 实际裁切：

| 资源方案 | 文件数 | 实测体积 | 结论 |
| --- | ---: | ---: | --- |
| 每个 `wp ID` 独立复制 | 446 | 约 1.15 MiB | 简单但有 260 份重复图片 |
| 按唯一动画资源导出 | 186 | 约 0.48 MiB | 已选方案 |
| 直接加载原版三张 atlas | 3 | 约 4.03 MiB | 体积更大且运行时裁切复杂 |

### 当前项目接入缺口

`src/ui/equipment-icon-assets.ts` 已预留 `definitionId` 专属图标优先、部位图标回退的接口，但专属映射当前为空。

另外：

- `InventoryItemView` 当前没有携带 `definitionId`。
- 侠客页已装备槽调用 `equipmentIconAsset` 时未传 `definitionId`。
- 侠客行囊仍显示“兵、甲、佩”等文字标识。
- 背包格和背包详情仍使用部位线稿 SVG。

因此仅填充 `uniqueEquipmentIcons` 不足以完成全界面替换，必须补齐 view model 和四处渲染入口。

## 已确认决策

1. 视觉处理采用“原版图标 + 现有品质边框”。原版美术表达装备身份，项目现有 0–9 品质边框、颜色、辉光继续表达品质。
2. 资源按唯一原版动画去重，输出 186 张图标，并生成 446 条装备 ID 映射。
3. 当前 `package.nw` 是装备图标生成链的唯一原版来源，不再混用 `_analysis/data.json` 或人工拼装的不同版本文件。
4. 186 张 WebP 和生成后的映射作为正式资源提交；`package.nw`、解包缓存和临时视觉页面不提交。
5. 替换范围覆盖背包格、背包详情、侠客行囊和侠客已装备槽。
6. 未知或异常装备 ID 继续回退到部位通用图标；空装备槽保留现有部位标识。

## 设计

### 生成入口与来源绑定

新增 PowerShell 入口脚本 `scripts/generate-zhutian-equipment-icons.ps1`：

- 默认定位相邻《诸天刷宝录》的 `package.nw`。
- 支持通过 `-PackagePath` 显式指定包路径。
- 在打开包并确认目标条目齐全后，才把所需 JSON 和三张图集提取到已忽略的 `scripts/tmp` 子目录。
- 调用装备生成器完成定义、图标裁切和映射输出。
- 正常 `npm run build` 不调用提取脚本，也不修改源码目录。

装备图标生成应与现有 `generate-zhutian-equipment.mjs` 的 446 件筛选结果共用同一批内存数据，不复制一套地点、套装或品质筛选规则。现有 `_analysis` fallback 应移除；缺少从同一包提取的来源时直接报错，并提示使用 PowerShell 入口。

### 图标裁切与命名

对 446 件装备读取 `wp` 第 3 列动画名，以动画名去重。每个唯一动画取“物品图标”动画的实际帧信息：

- sheet filename
- x/y
- width/height
- rotated

虽然当前 186 个目标帧均未旋转，裁切代码仍复用怪物脚本已经验证的 rotated 处理方式。裁切前验证存储宽高和图集边界，裁切后验证输出为 100×100。

输出目录：

`src/assets/equipment/zt/`

输出文件使用稳定的 ASCII 数字命名：

`zt_eq_<该动画所关联的基准wpId>.webp`

多个 `wp ID` 可以指向同一个 `iconKey`。清理旧产物前必须先解析并确认目标目录，只允许删除该目录内匹配 `zt_eq_*.webp` 的生成文件。

### 内容模型与资源加载

装备生成结果增加 `iconKey`，`EquipmentDefinitionV10` 同步暴露该字段。`equipment-icon-assets.ts` 使用 `import.meta.glob` 一次注册 `src/assets/equipment/zt/zt_eq_*.webp`，根据装备定义的 `iconKey` 返回 URL。

`equipmentIconAsset(slot, definitionId)` 保持当前调用语义：

1. 有效 `definitionId` 且能解析到 `iconKey` 和资源 URL时，返回 `source: 'unique'`。
2. 无定义、无映射或资源异常时，返回对应部位通用图标和 `source: 'slot'`。

不把原版资源路径保存进存档，也不修改 `EquipmentInstance`；现有存档继续只保存 `definitionId`。

### UI 接入

`InventoryItemView` 增加 `definitionId`，由 `main.ts` 的 `inventoryItemView` 从 `EquipmentInstance.definitionId` 传入。随后统一更新：

- 背包格：34px原版图标替换部位线稿。
- 背包详情：68px圆形展示区改为原版图标。
- 侠客行囊：34px原版图标替换文字部位印记。
- 已装备槽：46px图标按实际 `definitionId` 获取，不再只按 `slot` 获取。

现有边框、品质变量、阴影、锁定标识、等级、装备名称、套装名称、悬浮提示与交互属性保持不变。图片统一使用 `object-fit: contain`，并禁止拖拽和鼠标事件抢占。

## 错误处理与硬校验

生成器遇到以下任一情况必须失败，不得静默产出残缺资源：

- `package.nw` 不存在或无法作为 ZIP 打开。
- 任一要求条目缺失。
- 当前装备定义无法在 `wp` 中定位。
- `wp` 动画名为空或在“物品图标”对象中不存在。
- 帧坐标越界或裁切后尺寸错误。
- 映射数不是当前装备定义总数。
- 输出资源数与去重后的动画数不一致。

当前版本的回归快照应明确验证 446 条映射、186 张资源和 0 个缺失项；原版数据版本发生变化时，必须先审阅差异再更新快照。

## 验收标准

### 自动验证

- 已知普通装备和套装装备均返回原版图标。
- 共用原版动画的多个 `wp ID` 返回同一资源 URL。
- 未知 `definitionId` 返回对应部位通用图标。
- 背包格、背包详情、侠客行囊和已装备槽均渲染原版 `<img>`。
- 生成器全量覆盖、帧边界和数量断言通过。
- `npm test` 通过。
- `npm run build` 通过。
- `git diff --check` 通过。

### 浏览器验证

- 桌面宽度下检查背包页和侠客页四个图标入口。
- 窄屏下确认 28px/34px 图标仍清晰且不挤压名称、等级和部位信息。
- 检查不同品质边框、已装备、占用、锁定和空槽状态。
- 抽查古剑、文卷、物攻项链、盾牌及至少一组共用美术的套装装备。

## 非目标

- 不修改装备掉落概率、词条、套装机制或存档版本。
- 不提取当前项目未使用的其余原版物品图标。
- 不调整怪物、角色、技能或职业素材。
- 不删除八个部位通用图标，它们继续承担异常数据 fallback。
- 不把提取流程加入正常 build、启动或 CI。
