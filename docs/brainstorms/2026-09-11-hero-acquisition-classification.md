## 2. 证据与边界

- 基线为本机 `../诸天刷宝录/_analysis`，现有证据包标注版本1.2.2.0。逐项读取 js / zy / mg / wm / fb / wp / mc / shili，不依赖印象翻译。
- 本机当前 `package.nw` 与逆向基线并非字节一致，语义比较发现 js 仅3处命格ID差异：169号因陀罗第29列 280→279，176号芙蕾雅第30列 243→239，191号共工第31列 238→239；姓名、资质、章节、声望与价格字段一致。本文命格按逆向基线列出，不宣称是最新官方版本强度结论。
- `js[4]` 为原版初始职业，7..11为勇智体敏精，12..21为十项能力，22为声望，25为势力，26为价格，28..31为四个命格，35为大型副本招募分组。
- `刷新招募角色列表function`：普通名录按位面及势力筛选；召唤名录按 js[35] 与场景大型副本编号匹配。
- `招募角色function`：副本角色消费 wp[54+fb[副本编号][16]] 对应精魄、数量js[26]；166..193消费78号圣灵残魂。召唤是定向招募，不是随机抽卡。
- 同一函数把 js[4] 写入初始职业、js[28..31]写入存档35..38；新手套装入口明确调用招募165号赵云。
- `创建天命显示function` 在招募详情中读取 js[28+次数] 调用“建立命格图标方”，确认这些ID属于命格；[招募与命格运行时证据](../evidence/original-world/hero-acquisition-runtime-evidence.json)保留相关操作、条件与原事件路径。全表193条 js[33] 初始位阶均为1，不能把这个字段解释为卡池稀有度。
- 完整机器可读数据、文件SHA256与档案差异：[全角色分类JSON](../evidence/original-world/hero-acquisition-classification.json)。已有普通招募价格证据：[势力招募目录](../evidence/original-world/faction-recruitment-catalog.md)。

### 当前实现缺口

`src/content/heroes.ts` 的品级由章节统一生成，同章原版势力角色同品级；原版初始职业没有照搬，招募定义统一白丁。`src/combat/stats.ts` 当前没有接入这四个原版命格的完整属性链。十项能力白板已接入，仍不能据此断言原版战斗角色差异全部存在。

**高级池上线前应先确定角色卖点如何落在现有战斗中。** 可以选择性继承原版职业／命格，也可设计本作专长，但本轮不自动实施；避免仅提高获取难度而没有明显体验增益。

## 7. 建议的长期获取结构

1. **普通章节池常驻。** 解锁章节后永久开放；每章少量候选让目标清楚。四个池角色可以是2名名侠＋2名传奇的初稿，但不必机械平均概率。
2. **副本角色做第二阶段目标。** 原版已有7组主题，每组4人，适合后续副本与主题池联动。建议至少保留一种以副本表现积累的确定获取路线，避免所有强者都只剩花蛋蛋抽取。
3. **神系单列终局。** 28名形成4组题材，每组7人；不跨章污染早期池，不因“神”字就直接成为早期可抽奖励。
4. **非战斗价值也应有位置。** 管理、建造、研究、计略、锻造等能力可形成经营／成长目标；不能只按面板攻击给他们低档。
5. **无升星时，收集速度由首次获取节奏控制。** 不靠重复角色强制养成。重复处理、目标保底和自选兑换一起设计，且池中可获得的新角色数量应与每周蛋蛋收入预算对应。
6. **存量玩家只改新增获取路径。** 不收回已有侠客，不擅自把旧兑换价格折算成蛋蛋，不自动合并郭靖／蓉儿／康敏等文学身份可能重叠但游戏ID不同的角色。

### 需要特别校正的点

- 13章全部开放会有52名常规池候选＋28名副本候选＋28名神系目标，不能把108人同时放一个常驻大池；定向目标必须能收敛。
- 兑换队伍要覆盖可靠输出、生存、恢复／功能辅助。第3章兑换侧原职业偏学者，第7章偏弓手；这是职业分布事实，不等于无法转职，但需逐章验证可推进阵容。
- 原版华佗为女性记录、原名“熬烈”“蓉儿”“空竹”等均按原表保留；不以外部故事印象自动纠错。
