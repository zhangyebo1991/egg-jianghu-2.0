# 战斗核心机制与怪物技能对齐诸天

- 日期：2026-08-13
- 状态：已确认

## 背景与目标

气机 ATB（50/√速度）、A²/(A+D) 乘区伤害链、命中/暴击/吸血、3×5 索敌已对齐原版；但能量制自创（0–100，行动 +5/普攻 +10 硬编码）、`ACTIVE_SKILLS` 为空导致实战全普攻、状态系统是独立数值型骨架。本阶段把战斗核心机制（能量、冷却、buff、护盾、特殊机制）与全部怪物技能（首领四技能 + 小怪职业普攻，含召唤）对齐《诸天刷宝录》。

## 核心需求

### 能量机制重做（玩家与怪物同套）

- 真气 0–100 改为能量点 0–5：`maxEnergy = 5`。
- 初始能量 = 属性 sx28；每次行动开始按 sx29 能量回复回能（白板 1 点）。
- 技能消耗 = `jn` 列 19 能量档（0–5）。
- 冷却 = 能量档 × 4 秒 × (1 − sx37 技能冷却/100)；替换现行硬编码 +5/+10。
- 证据：`获得能量值function` clamp 0–5（c3runtime 55508）、CD=列19×4（10364）、行动开始读属性 29（55183）。

### 技能系统激活（jn.json 导入）

- 扩展生成脚本：导出被引用技能（130 首领 × 4 槽去重 + 10 种职业普攻 + 召唤物所需）为 `src/content/skills.ts`，注册进战斗 registry，填掉 `ACTIVE_SKILLS` 空表。
- 字段对齐：
  - 威力系数：`round((列16 + 列17×(等级−1)/10) × 列29/100)`（c3runtime 50100）。
  - 元素（列 5）、多段命中（列 36）、能量档（列 19）。
  - 范围：列 37 → `fw.json`（类型 目标/地面/自身/随机 + 覆盖格数）翻译成现有 targeting 形状枚举（单体/十字/一路/全体/随机）。
  - 附加 buff（列 21–24：id/几率/持续/层数）、增效 buff（列 41–43）。
- 行为类型（列 15）全支持：近战攻击、远程攻击、生命治疗、自身治疗、自身护盾、自身状态、我方状态、我方复活、我方进度（推行动条 gauge 加值）、增加能量、被动（进战挂属性，列 8–11）、召唤。
- 首领 520 技能槽分布参考：伤害 290、buff 109、治疗 41、护盾 13、复活 17、推条 13、加能量 6、召唤 20、被动 10。

### 怪物技能配置

- 首领：`js.json` 列 28–31 四技能 → `skillIds`（130 首领全部可按名字匹配）；AI 沿用现有四槽 selectSkill（能量够 + CD 好按栏位优先，否则普攻）。
- 小怪：`dr` 列 3 模板（1–10）→ `zy` 职业普攻（白丁攻击/护卫钝击/武夫铁拳/学者冰击/弓手射击/方士包扎/异能者猛击/圣教徒圣击/侠客劈砍/武士突刺）；方士型小怪会治疗队友；精英同小怪普攻。

### buff/状态系统重做（buff.json 68 条导入）

- 改为属性修正型：buff 挂「属性 id + 修正值 + 层数上限 + 持续时间」，参与属性面板计算。
- 控制类 = 速度修正（sx113）−100：眩晕/麻痹/冰冻/静止，行动条停涨（有效速度 ≤0 时 gauge 不涨）。
- 无敌 = 受所有伤害 −95%；DoT（毒/燃/流血）走 buff 伤害计算。
- 持续时间受 sx34/35 增益/减益时间修正；弃用自创的 controlResistance/控制递减。

### 计算机制补全

- 护盾：护盾计算公式与伤害吸收（对齐 c3runtime 58053）。
- 治疗接入受疗效果 sx38。
- 增效 buff 系数（列 41–43）接入伤害乘区链。
- 元素克制乘区（实现时逆向 c3runtime 58117 `克制元素编号function`）。

### 召唤系统

- 召唤物单位：数据映射（`jn` 列 51 召唤物 id，实现时逆向「生成召唤角色」函数族）、召唤时间/数量/强度属性 sx31–33。
- 站位：施法方空格放置；进现有 `summons` 容器参战（时限倒计时已有）。
- 立绘：从「角色形象」合图补切召唤物形象。

### 玩家侧（本阶段边界）

- 玩家仍只打职业普攻，但普攻 id 对齐 `zy` 列 6（41 职业各自普攻，含元素/远程/治疗差异），替换固定 1.0 系数的 `base_${careerId}`。
- 300 门武功不接入战斗（技能类型卡按 career-zhutian 既定规划留下一阶段）；四槽 UI 维持现状。

### UI

- 战斗日志补齐技能名、治疗、护盾、召唤、复活事件。

- 平衡基线：怪物面板仍走现有 scale 公式；技能只改变行为与倍率结构。
- 中文文案；不自动提交 Git。

## 方案与决策

### 决策标准

- 机制规则一律以 c3runtime 逆向证据为准（能量 0–5、CD=档×4、buff 属性修正型、控制=速度−100）。
- 数据一律从 package.nw 包内同版本表导出（jn/fw/buff/js/zy），沿用怪物替换阶段的生成脚本管线。
- 特殊机制全做（含召唤），玩家技能卡不进本阶段。

### 选定方向

能量点制 + jn 技能 registry + js/zy 怪物技能配置 + buff 属性修正型重做 + 护盾/受疗/增效/克制补全 + 召唤系统，一次交付完整原版战斗表现。

### 选择理由

用户要求怪物技能与出手/计算/能量机制全面对齐，且明确召唤一并做。现有引擎的四槽 AI、targeting 形状库、statuses/summons 容器、事件总线都是现成扩展点，全量复刻的边际成本可控。

### 主要备选

- 召唤类跳过（技能槽空置）：省召唤物数据与立绘管线，但十几个 boss 战斗表现缺失，用户否决。
- 保留 0–100 真气制只做技能：能量档/CD 公式无法对齐原版，技能数值需要全部自行标定，放弃。
