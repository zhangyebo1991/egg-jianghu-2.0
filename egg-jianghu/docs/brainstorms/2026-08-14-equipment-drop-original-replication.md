# 装备掉落原版机制复刻

- 日期：2026-08-14
- 状态：已确认

## 背景与目标

当前掉落装备使用自定义五档品质、单条基础属性和自定义附词条区间，与本机《诸天刷宝录》源码及数据不符。本轮将普通装备、特殊装备和可掉落套装件的随机属性生成、属性结算及界面展示统一改为原版机制。

## 核心需求

- 每件装备按其装备类型生成两条核心词条；两条核心系数分别独立在模板系数的 90%–110% 掷值，实际系数保留一位小数。
- 核心词条展示实际结算值及实际百分比；百分比由 `实际系数 / 模板系数` 得到，不使用虚构范围。
- 品质使用 0–9 十档数值。品质对应附词条数为 `0/1/2/2/3/3/4/4/5/5`。
- 每条附词条系数按 `round(random(30 + quality×10, 110 + quality×10 - 0.01) × 100) / 100` 生成。
- 附词条评价为：`<60 E`、`<80 D`、`<100 C`、`<120 B`、`<140 A`、`<160 S`、`<180 SS`、其余 `SSS`。
- 候选属性严格读取 `zbct.json` 对应装备类型列，范围为属性 6–59；重复值保留额外权重，同一装备允许重复附词条。
- 随机数消费顺序固定为：核心 1、核心 2、全部附词条系数、全部附词条类型。
- 套装件根据 `wp.col29 -> shili 对应行 -> shili.col22` 获取元素。元素为 0 时不限制；非 0 时，元素词条只允许对应属性对，并通过重抽保持原版 RNG 消费方式。
- 原版属性结算使用装备属性等级 `itemLevel×10`、强化星级 0；核心权重 100，附词条权重 50。
- UI 显示 `品质 0` 至 `品质 9`；附词条显示实际值及 E–SSS 评价，评价颜色遵循原版。

## 约束

- 原版机制只采用本机 `_analysis` 数据和运行时源码证据，不靠猜测补齐。
- 套装件参与掉落；至宝、勋章不会掉落，本轮不处理。
- 不修改当前项目已有的套装掉率和掉落件数规则。
- 不实现套装效果。
- 新装备结构不迁移旧存档，存档版本升至 v16 并使用新 key。

## 方案与决策

### 决策标准

- 数据来源和随机顺序必须能与原版逐项对照。
- 所有可掉落装备使用同一条生成与结算链，避免 UI、战斗和存档各自解释数值。
- 保留当前项目的掉落池整合规则，只替换已确认错误的装备属性机制。

### 选定方向

生成器从 `wp.json`、`zbct.json`、`shili.json` 等原版数据导出双核心模板、加权附词条池、固定品质和套装元素；运行时只保存实际核心/附词条系数，由统一公式计算面板值并供战斗与 UI 复用。

### 选择理由

该方向保留原版数据的重复权重与套装元素重抽语义，也能让核心百分比、词条评价和战斗生效值来自同一份真实随机结果。

## 已确认基准

- 古剑：物攻 220、物理增伤 100。
- 物攻项链：物攻 40、闪避修正 200。
- Lv.5 物攻项链在核心系数约 37.4 时，物攻结算为 12；闪避模板实际系数约 189.4 时，闪避修正约为 5.84%。
- 普通敌人、精英、首领分别映射原版品级 1、2、4；敌人基础品质权重分别采用原版表。
- 普通装备品质为敌人基础品质加当前位面额外品质 1；套装件固定品质 5。
- 装等公式为 `floor((难度系数 + 9) / 10) + ((物品品质 - 1) × 2)`，品质 0 必须按原公式参与。
